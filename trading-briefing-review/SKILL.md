# 早读复核 (briefing-review)

## 定位与权限边界（硬约束）
- 对人工正式早读（`交易体系/财经早读/YYYY-MM-DD-财经早读.md`）做第三方审阅
- **唯一输出**：`交易体系/早读复核/YYYY-MM-DD-早读复核.md`（一份文件）
- **永不修改/回写正式早读**；vault 写入仅限 `交易体系/早读复核/` 文件夹（2026-09-08 起，用户解禁前有效）
- 审阅姿态：**不反驳、不支持、不生成新观点**，只做客观标注；人工正式早读的修订权在用户

## 触发与前置
- 用户说"复核早读 / 早读复核"，在正式早读入库后**手动触发**（模式验证期不自动化）
- 前置检查：正式早读文件存在（不存在则停止并告知）；自动层文件（同日 `YYYY-MM-DD-财经早报-自动草稿.md`）与 RSS 简报（`交易体系/早报数据/rss-digest/digests/同日.md`）存在则一并加载，缺失则在报告中注明

## 输出模板（三节，单文件）

```
# 早读复核 - {日期}
> 复核基准时点：开盘前（09:15）可得信息 · 复核执行时间：{timestamp}
> 复核覆盖率：行情表 {n}/{m} 项 · 事实类 {k}/{t} 项（web_search 核查）
> 覆盖范围外（不判定对错）：主观解读、docx 独有非公开信息（此部分走第二节记忆审阅）

## 一、数据复核（四态判定）
| 正式稿项 | 正式稿值 | 自动层/检索值 | 判定 | 说明（含时点标注） |

## 二、主观判断的客观审阅（逐条三态标注）
## 三、盲区标记（≤3 条）
```

### 四态判定规则（第一节）
- `一致`：偏差 <0.5% 或完全相符
- `口径差异`：时点/口径可解释（自动层=最近两根日线收盘 vs 正式=15:00→次日6:30），**不算错误**
- `过时-需修正`：正式稿发布时无误，但以开盘前最新信息看已变化 → 附最新值+时间戳（哪怕不是错误也要修正）
- `疑似错误`：超出时点可解释范围且无法解释 → 给出证据与建议核实方向
- 每项必须带时点标注；复核若在盘中/盘后执行，禁止用盘中数据倒推正式稿"错误"（基准=开盘前）

### 记忆审阅规则（第二节，硬约束）
对正式稿中的主观判断逐条标注，只允许三态：
- `【记忆-一致】` / `【记忆-冲突】`：必须附记忆条目路径与沉淀时间（domain-memory 交易领域检索）
- `【记忆-无覆盖】`：明说无覆盖，禁止硬套类比生成新观点

记忆无覆盖时的**常识辅助**（约束）：
- 强制标签 `【常识-非记忆】`，与记忆引用明确区分
- 仅两类用途：① 事实性 sanity check（数字加总、因果链硬伤才出手）② 标注"偏离市场共识的程度"——**不评对错**，反共识本身当信息呈现（提示"此处与市场共识相反，是有意还是疏忽请自查"）
- 禁止用市场平均观点否定用户的独立判断
- 常识判断连续多次与后续复盘结论相反 → 反向沉淀为交易记忆（负样本），该类常识让位

### 盲区标记规则（第三节）
正式早读未提及、但同时满足以下两条的信息：
- 六类关注方向命中：商品 / 存储AI / 美股宏观 / 地产银行 / 地缘 / IPO打新
- 显著性阈值：商品单日涨跌 >2%、指数新高/新低、利率关口（如 30Y 破 5%）、政策落地、地缘升级
- **最多 3 条**；候选超过 3 条 → 判定阈值过松，先收紧阈值再输出
- 每条附：为何重要 + 跟踪字段（后续 3 日是否成为正式早读主题/盘面主线：命中/未命中）

## 定期校准（每 10 个交易日或并入周度复盘）
- 回看历史复核文件第三节，统计盲区命中率；命中率低 → 修改本 skill 阈值定义（注明调整日期与依据，版本化）
- 同时统计第一节的误报率（把口径差异误判为疑似错误的次数）

## 与其他 skill 的分工（消歧）
- `trading-briefing-fetch`：只产出自动层数据文件（本 skill 的输入之一）
- `trading-contradiction-check`：跨日逻辑矛盾（前日预判 vs 实际）；本 skill 管当日事实核验
- `obsidian-reconcile`：全 vault 扫描；本 skill 只看当日早读
- `domain-memory`：记忆读写走其工作流；本 skill 只读引用（审阅用），产出教训时经由其写入工作流

## 模式验证期（2026-09-08 起）
- 手动触发、不自动化；编辑权限仅限 `交易体系/早读复核/`，解禁由用户决定
- 跑通判定标准：连续 5 次复核 ① 无越权写入 ② 数据复核误报率可接受 ③ 盲区命中可用 ④ 记忆审阅无硬套
- 验证期内发现模板/阈值问题 → 直接修订本 skill 并提交推送
