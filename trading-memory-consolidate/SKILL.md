# 交易记忆归纳整理工作流（trading-memory-consolidate）

> **Vault 路径**：`{VAULT_PATH}`（占位符，由 agent 从 MEMORY.md 读取本机实际路径后替换）。
> ⚠️ Vault 可能在 OneDrive 下——批量移动用 pwsh 安全；单篇写入分批。
> 📅 立法来源：2026-09-07 首次全量整理（22 篇 → 八区总表 + 归档），方法论与坑全部来自实战。

## 0. 开工前：方法论五问（必答，向用户显式输出后再动手）

> 这五问是本 skill 的灵魂。跳过直接干活 = 机械归档，丢失整理的核心价值。

**Q1 交易记忆在体系中的作用是什么？**
- 记忆层级：MEMORY.md（稳定规则索引）→ **交易记忆（模式 + 证据链）** → 每日复盘（流水）→ wiki（知识）
- 记忆的三个独特功能：**跨周期模式识别**（"二日游 2/3 熄火率"单日复盘看不出，靠累积统计）、**纪律案例库**（否决案例与执行案例同等重要，甚至更重要）、**规则演化证据链**（布油锚为什么是布伦特——防止未来重新犯错或规则回退）
- 向用户复述作用 = 校准双方对任务价值的共识，避免整理成"机械归档"

**Q2 用户的整理想法是否存在缺陷？（主动指出，不迎合）**
- **缺陷1——"冲突"≠"错误"**：记忆间冲突必须分三类处理——
  - **演化**：时间序列上的规则迭代（量能门槛 2.5→2.2→2.0 随市场中枢下移）。旧版不删，标注"被 XX 取代"，保留证据链
  - **真冲突**：同一时间口径下互相矛盾 → 归因裁决，明确当前有效版本
  - **互补**：不同维度各说各话 → 合并
  - 把演化当冲突"消灭" = 丢掉"规则为什么是现在这样"的证据链，未来会重新犯错或回退
- **缺陷2——归档 ≠ 消失**：归档后若总表不挂进 MEMORY.md + 交接文件的"新会话必读"链路，总表就是写了没人看的死文档。挂链是整理的一半工作量
- **缺陷3（易被遗漏）——记忆会腐烂**：不更新失效标注的记忆是毒药（实例：8/24 记忆"22.00=裁判位补仓"被 8/26 推翻后未标注，两个月后读到会误导）。总表必须为每条标注**当前有效状态**

**Q3 用什么维度归纳才能发挥记忆的作用？**
- ❌ 按日期/按标的组织 = 检索价值低（和复盘没区别）
- ✅ **按决策场景组织**："出现什么信号 → 历史上怎么做 → 结果如何 → 实证几次 → 最新验证时间"——盘中验证时直接对照，而非翻历史

**Q4（补充）否决案例与执行绩效是否入表？**
- "没做的事"（回补否决/防火墙冻结）与"做的事"（减仓执行）同样重要；**执行绩效必须诚实记录亏损**（如双轨制首轮 -5.2%），只记成功 = 体系自欺

**Q5（补充）记忆的半衰期分层？**
- 永久层：铁律与纠错（收盘口径第一性）／模式层：有实证统计但可被新市场结构修正（二日游熄火率）／快照层：资产锚价格等易变信息（**不入总表**，写了就腐烂）

## 1. 触发时机

- **用户手动触发**（本 skill 不自动运行——全量审阅成本高，需用户确认）
- 建议节奏：新记忆累积 ≥8-10 篇，或发生重大规则变更（如冻结令/体系重构级）之后
- 触发后先向用户输出方法论五问的回答，**经用户认可后再执行**

## 2. 前置步骤

1. 时间校验（Get-Date）
2. 读 `~/.dsh/MEMORY.md`：Vault 路径、记忆维护规则、当前冻结状态
3. 读交接文件（若存在）：确认当前策略状态（冻结令等直接影响记忆"当前有效"判定）
4. 确认整理范围：全部 / 增量（自上次整理后）

## 3. Step 1：批量审阅全部记忆

```powershell
Get-ChildItem "{VAULT_PATH}\交易体系\交易记忆" -Filter "2026-*.md" |
  Sort-Object Name |
  ForEach-Object { Write-Output "`n########## FILE: $($_.Name) ##########"; Get-Content $_.FullName -Encoding UTF8 -Raw }
```

- 每篇提取五要素：**rules（frontmatter）/ 预测假设 / 实际结果 / 偏差分析 / 规则修正**
- "资产锚状态备忘"类内容 = 快照层，**不进总表**（易腐烂）

> ⚠️ **实战坑：pwsh 输出截断**。文件多时输出超上限会被截断并给出 spill 文件路径（`C:\Users\...\dsh-spill-...\xxx-pwsh.txt`）。
> 处理：用 grep 在 spill 文件中搜 `FILE: 2026-` 确认哪些篇没读到 → 用 read 工具按 offset 补读缺失区段。**必须逐篇清点，防止漏读**。

## 4. Step 2：分类归因（五类 + 口径统一）

对发现的每处不一致，先归入五类之一再行动：

| 类别 | 判定 | 处置 |
|------|------|------|
| **演化** | 时间序列上的规则迭代（旧版被新版取代） | 总表标注"当前有效版本"；旧记忆归档保留，不删不改 |
| **真冲突** | 同一时间口径下互相矛盾 | 归因后裁决，写入总表；必要时报用户裁决 |
| **互补** | 不同维度各说各话 | 合并为一条复合规则 |
| **事实错误** | 当时记录的口径就是错的（如成本误记） | 进总表 F 区纠错清单 + 防复发机制 |
| **覆盖缺口** | 复盘中有重大裁决但无对应记忆文件 | 进总表 G 区补录（指向已归档复盘），不伪造记忆 |

另做**口径统一**：同类统计表述不一致时统一（例："二日游"= 爆发日 T，T+1 熄火率 2/3；"第 3 日裁决"= T+2——两个说法是同一模式的两段，不是两个模式）。

## 5. Step 3：写记忆总表（`00-交易记忆总表.md`，八区结构）

> 命名必须 `00-` 前缀——归档通配是 `2026-*.md`，无日期前缀避免被误移。

| 区 | 内容 | 要点 |
|----|------|------|
| **A 量能与判据** | 演化链 + 体系级发现 | 演化链完整呈现（2.5→2.2→2.0）；"体系级发现"单独标注（如绝对门槛随中枢下移失效 → 改相对量能） |
| **B 模式识别** | 高频统计规律 | 每条：实证次数 + 操作含义（"出现 X → 做 Y"） |
| **C 纪律铁律** | 全部多次实证的纪律 | 每条列实证案例（N 次实证的来源） |
| **D 案例库** | 正确否决 / 正确执行 / **执行绩效** | 绩效诚实记录亏损与处置正确性 |
| **E 标的演化链** | 每标的一条链 | **当前有效版本加粗**；旧版不删 |
| **F 纠错记录** | 错误 → 纠错 → 防复发机制 | 三列缺一不可 |
| **G 覆盖缺口** | 补录无记忆的重大裁决 | 指向已归档复盘，不伪造记忆 |
| **H 冻结状态速查** | 当前生效的冻结/豁免（如 CPI 冻结令） | 让总表"当下可用"而非纯历史 |

**每条规则的强制格式**：规则 + 实证次数 + 最近验证时间 + 状态（✅有效 / ⚠️过时 / 🔧待重估 / 🧊冻结）。

## 6. Step 4：归档原始记忆

```powershell
$dst = "{VAULT_PATH}\交易体系\交易记忆\记忆归档"
New-Item -ItemType Directory -Force $dst | Out-Null
Get-ChildItem "{VAULT_PATH}\交易体系\交易记忆" -Filter "2026-*.md" | Sort-Object Name |
  Move-Item -Destination $dst
```

- **移动而非删除**（铁律：历史文件必须全部保留）
- Obsidian wikilink 按文件名解析（不依赖路径），批量移动不破坏 `[[引用]]`
- 移动后写 `记忆归档/交易记忆归档索引.md`：每篇一行（日期 / 主题 / 核心产出 / 已知问题标注——如"⚠️ 成本 4.77 为当时错误口径"）

## 7. Step 5：挂链接（归档 ≠ 消失）

1. **MEMORY.md** 记忆维护节：加总表指针（路径 + "新会话接手必读" + 后续维护方式）
2. **交接文件** 文件地图：更新交易记忆目录结构（总表 + 归档）
3. 总表内引用归档文件用 `[[YYYY-MM-DD-交易记忆-主题]]` 文件名形式（Obsidian 按名解析）

## 10. 常见错误（历史教训）

1. **把演化当冲突消灭**——丢证据链，未来回退重蹈覆辙
2. **归档后不挂链**——总表成死文档，整理白做
3. **按日期组织总表**——检索价值趋零
4. **pwsh dump 截断未察觉**——漏读记忆导致总表缺区
5. **总表收录易变资产锚**——两周后全部过期腐烂
6. **只记成功不记失败**——执行绩效失真，体系自欺
7. **归档通配误移总表**——用 `00-` 前缀规避
8. **整理时顺手"修正"原始记忆**——❌ 原始记忆是历史证据，只移动不改写；修正写入总表
