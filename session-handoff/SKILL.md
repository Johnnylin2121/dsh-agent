# 会话交接工作流

> **定位**：把一个即将被上下文掐断的会话，压缩成**下一个会话（或另一个agent）能独立接手**的自包含文档。
> **域无关**：本skill不假设任何领域、不预设任何结论。**所有内容由激活它的agent从本会话实际发生的事中自行梳理。**

---

## 核心原则

### 1. 证据优先，不凭记忆
交接内容必须**从可核验的证据**推导，不是回忆。可用证据（按可得性）：
- 本会话写入/修改过的文件（路径 + 变更内容 + 时间）
- 日志、状态文件、计划文件、任务清单
- 记忆文件、决策记录
- 本会话对话中的**用户原话**（尤其是纠正与决策）

> ⚠️ 上下文被压缩或截断时，**主动去读上面这些证据**，不要靠残存的对话印象编。

### 2. 宁缺勿造
某节没有内容 → 明确写「**本会话无**」。
**绝不允许为了让交接书看起来完整而编造内容。** 编造内容比留空危害大得多——下一个会话会当真。

### 3. 自包含
下一个会话**只能拿到这份交接书 + 用户提供的必要上下文**。任何"上一轮说过/刚才提过"的内容都必须落进文件。
检验方法：假装你只见过这份文件，能不能接着干？能，才算合格。

### 4. 不越权
交接是**移交状态**，不是**移交决策权**。交接书里不要替接收方做判断。

## 交接文件结构

> 以下是**槽位**，不是模板答案。每节内容由 agent 依据本会话实况填写。
> 无内容的节写「本会话无」并删除该节标题——**不要留空标题**。

| # | 节 | 填什么 |
|---|---|---|
| **1** | **会话标识** | 什么主题的会话、起止时间、领域、**接手方是新会话还是新agent** |
| **2** | **原始目标** | 用户最初要什么（**用用户原话**）。多目标则分条列 |
| **3** | **完成进度** | 逐项：✅完成 ／ 🔄进行中（含卡在哪一步） ／ ⛔阻塞（缺什么） ／ ❌已放弃。带产物路径或标识 |
| **4** | **当前位置** | **此刻正在做什么/接下来第一件事**。要具体到可执行，不是"继续跟进XX" |
| **5** | **关键决策** | 本会话已定的决策 ＋ **依据** ＋ **谁拍的板**。区分「我建议」与「用户已定」 |
| **6** | **未决问题** | 需要用户/他人裁决的事：问题、影响、可选项、**回执格式**（让对方能一句话答复） |
| **7** | **生效的约束与规则** | 本领域正在生效的规则/规范/禁止项。**给释义，不只给编号**——接收方可能没读过原文 |
| **8** | **关键注意事项** | 环境坑、工具限制、路径依赖、易踩的外部因素。**"如果只记住三件事"放这里** |
| **9** | **本会话的错误与失误** | agent 自己判错的：错在哪 → 正确做法 → 是否已修正。含被用户纠正的 |
| **10** | **踩过的坑** | 见「坑库机制」。本会话新增的坑 |
| **11** | **可用资源** | 文件路径、命令、接口、环境变量、注意事项。**可复制的具体内容** |
| **12** | **续接入口** | 接手方第一句话该做什么／第一条命令该跑什么 |

## 执行步骤

```
1. 盘点证据 —— 列出本会话所有写入物、决策、用户纠正
2. 读坑库   —— 载入继承的坑，识别本会话新增了哪些
3. 定位置   —— 确认"此刻在哪、下一步第一件事是什么"
4. 写交接书 —— 填槽位，无内容就删节
5. 更新坑库 —— 本会话新增的坑追加进去
6. 留痕     —— 若涉及写入外部系统，按该系统规范留痕
7. 给复制块 —— 短，只指向路径
```

### 关于留痕（第6步）
如果本会话的规范要求写入留痕（如某知识库的"写入者+时间"规范），**在写交接书前先确认该规范**，不要照搬别处的做法。以目标系统自己的规则为准。

### 第7步的复制块
```
请先读这份交接文件再接手：<路径>

<一句话说明接手后第一件事>
读完直接告诉我你打算怎么开始。
```
> 📌 **不要把交接全文贴进对话**。若接收方能读文件路径，贴全文只是双向浪费。
> 若接收方读不到文件（如跨平台/无工具），才贴全文。

## 坑库机制

交接的价值一半在"现在什么情况"，另一半在"**别再踩同一个坑**"。后者靠累积，不能靠单次会话记忆。

**每次执行本skill时**：
1. 读取既有坑库（路径见下方）
2. 识别本会话新增的坑 → 追加
3. 坑条目格式：
   ```markdown
   ### <编号> <简标题>
   - **类别**：用户纠正 / 判断纪律 / 数据工具 / 流程环境 / 沟通表达
   - **时间**：YYYY-MM-DD
   - **❌ 错**：具体错误行为
   - **✅ 正解**：怎么改；用户纠正请附原话
   - **📌 是否已制度化**：规则编号，或"未立规则"
   ```

**坑库位置**：`<skill目录>/references/pitfalls.md`
同域的多个agent可各持副本，也可汇入共享位置（如团队知识库）——**关键是接手方能读到**。

## 收尾自检

```
☐ 结构各节非空（或已删除空节），无占位文字
☐ 每条决策标明了「谁拍板」与依据
☐ 未决问题都带可执行的回执格式
☐ 「当前位置」具体到可立即执行
☐ 错误与失误诚实记录，含被用户纠正的
☐ 约束规则给了释义，不只给编号
☐ 坑库已更新
☐ 接手方只凭这份文件能续接（自包含检验）
☐ 全文无编造内容
☐ 复制块只含路径
```

## 本工作流自身的坑

| ❌ 错 | ✅ 正解 |
|---|---|
| 交接书写成"现状汇报"，没有下一步 | 「当前位置」必须是可立即执行的动作 |
| 未决问题只列问题不给选项 | 每项给可选项 ＋ 回执格式，对方才能一句话答复 |
| 用对话记忆里的数字 | 记忆里的数值可能已过期，**去读证据文件** |
| 复制全文到新对话 | 优先只给路径 |
| 交接书塞进领域假设 | 本skill域无关，领域内容由 agent 实测填 |
| 忘了写"本会话的错误" | 错误是最有价值的部分，agent 的判错记录能防止重复 |
| 留痕时照搬别处规范 | 以**目标系统自己**的规范为准 |
