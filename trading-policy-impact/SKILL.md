# 政策事件追踪

## 触发条件

- 财经早读同步时，对重大政策/事件自动触发
- 用户说"追踪这个政策"、"分析 XXX 政策影响"

## 重大政策判定标准

符合以下任一条件的政策/事件视为重大：
- 国务院、央行、证监会、发改委等核心部委发布
- 涉及行业性政策调整（如补贴、限产、准入）
- 地缘政治事件（如制裁、冲突、贸易摩擦）
- 宏观数据超预期（如 CPI、PMI、GDP）
- 重大产业事件（如技术突破、行业并购潮）

不符合的日常政策动态不触发追踪，仅在财经早读中记录即可。

## 执行流程

### Step 1: 识别政策事件

从财经早读文件中提取：
- 政策/事件名称
- 发布机构
- 发布日期
- 涉及行业/板块
- 核心内容（3-5句话）

### Step 2: 影响链路分析

通过 web search 搜索：

```
"{政策名}" 影响 板块 OR 行业 OR 受益 OR 利空
"{政策名}" 历史 对比 OR 先例
"{政策名}" 落地 实施 细则
```

**事件快讯/情绪补充（本机 HTTPS 修复前，用工具抓取）**：
- ⚠️ 本机 schannel 出站 TLS 损坏，curl/xueqiu 工具不可用；用 `dsh-market.mjs`（node.fetch）：
  ```bash
  MK="$HOME/.dsh/skills/_shared/dsh-market.mjs"
  node "$MK" get "<新闻/公告/研报 url>"   # 抓页面转纯文本
  node "$MK" index / stocks / sector / sina   # 行情复核
  ```
- `node "$MK" get` 抓取政策发布后的即时快讯与市场解读页面，作为 web search 的补充。
- `node "$MK" sector` / `stocks` / `sina`：给受影响板块/标的口径复核与实时数据（`"市场反应追踪"` 表格的数据来源）。

分析维度：
1. **直接受益**：政策直接利好的行业/公司
2. **间接受益**：通过产业链传导受益的行业/公司
3. **可能受损**：政策利空的行业/公司
4. **影响时滞**：政策从发布到市场反应的预期时间

> **冲突规则**：东财与新浪/页面数值不一致时，在追踪文件"市场反应追踪"中显著标注（`⚠️ 数据冲突`），不自动取信任一；板块涨跌幅类以东方财富为基准。

### Step 3: 映射到现有知识库

从 `{VAULT_PATH}/wiki/entities/` 和 `wiki/topics/` 中筛选相关实体和主题：
- 匹配 tags 和 frontmatter 中的行业/板块关键词
- 标注每个受影响标的的受益/受损方向和逻辑

### Step 4: 搜索历史先例

搜索类似政策的历史市场反应：
- 同类政策过去发布后的板块表现
- 持续时间和幅度
- 当前环境与历史的差异

### Step 5: 写入追踪文件

输出路径：`{VAULT_PATH}/wiki/topics/{政策名}-政策追踪.md`

同时更新相关 entity 文件的 `sources` 字段，引用新创建的追踪文件。

## 状态流转

```
tracking → verified（政策影响已兑现）
tracking → expired（政策影响已消退/证伪）
```

复盘中验证政策影响时，更新 `status` 字段。若影响已兑现或消退，将文件移入 `wiki/synthesis/` 归档。

## 格式规范

- 涨跌幅保留2位小数
- 使用 Obsidian 兼容的 Markdown 语法
- frontmatter 中 `related` 必须链接到相关的 entity 和 topic 文件
- `status` 字段只能是 `tracking`、`verified`、`expired` 之一
