# 个股深度扫描

## 触发条件

用户说以下任一短语时触发：
- "深度扫描 XXX"
- "研究一下 XXX"
- "XXX 怎么样"
- "帮我看看 XXX"

仅手动触发，不在复盘或盘前预测中自动执行。

## 数据源

全部免费、无需 API Key：

| 数据 | 来源 | 获取方式 |
|------|------|----------|
| 实时行情 | 东方财富 API | `push2.eastmoney.com` |
| 近期公告 | 东方财富 | `data.eastmoney.com/notices/stock/{code}.html` |

## 数据多源校验（东财口径基准 + 新浪/雪球交叉）

> ⚠️ **本机 Windows schannel 出站 TLS 曾损坏**，curl/Invoke-WebRequest 不可用；统一用 `dsh-market.mjs`（node.fetch/OpenSSL）；**DSH 工具面的 `xueqiu_*` 工具可用**（quote/kline/search），纳入交叉源：
> ```bash
> MK="$HOME/.dsh/skills/_shared/dsh-market.mjs"
> node "$MK" index / stocks / sector / sina / kline / get "<url>"
> ```

- **行情/技术面**：主用东方财富（`stocks`，口径基准），用 `sina`（实时含买卖盘）与 `xueqiu_quote/kline` **交叉复核**；K线走 `kline`（无图，纯数据）。
- **个股主力资金**：`dsh-market.mjs` **无个股资金子命令**（仅 index/stocks/sector/sina/kline/get）——用**三层代理**：①板块资金（`sector`）②K线量能趋势（`kline`，价量背离判断）③Vault 历史复盘主力记录（`交易体系/交易记忆/`+复盘，如南山 8/17-8/20 主力序列）；最后可提示用户用交易终端复核。
- **舆情/事件核实**：`web_search`（优先）+ `node "$MK" get "<网页>"` 补充；**商品/公告/事件异动时（如期货单日大幅波动、公司公告突发）必须 web_search 核实驱动再写入扫描**——8/26 巴西复产核实即靠此（8/17 减产催化 1 周内回吐的完整证据链）。
- **代码/标的名定位**：`node "$MK" get "https://searchapi.eastmoney.com/api/suggest/get?input={名}&type=14&token=D43BF722C8E33BDC906FB84D85E326E8"`，或让用户确认；`{VAULT_PATH}/wiki/entities/` 找不到对应 entity 时优先这样做。
- **冲突规则（硬性）**：多源数值不一致 → 在扫描报告"基本面快照 / 技术面"中**显著标注**（如 `⚠️ 数据冲突：东财 vs 新浪`），**不自动取信任一**；估值/财务类以东方财富口径为准。
- **机构评级接口**：`data.eastmoney.com/report/stock/{code}.html` 常返回空（8/21 实测 RPT_RES_REPORT 无数据）——**拿不到时机构动态栏以自评替代并标注"自评"**，不硬等。
- **公告接口**：`data.eastmoney.com/notices/stock/{code}.html` 若 `get` 返回空，改用 np-anotice 公告接口或 web_search 补齐（近30天标题+类型即可）。
- 写入扫描文件用 `obsidian_write`（已装 dsh-obsidian 时）。

## 执行流程

### Step 0: 时间校验（8/26 起）

- 获取当前日期，确认扫描数据日期口径（近30天公告/K线截止日）；**增量复扫时确认基线扫描日期**（见 Step 1）

### Step 1: 确定标的 + 模式判定

- 用户提供股票名称或代码；若提供名称，在 `{VAULT_PATH}/wiki/entities/` 中查找对应 entity 文件获取代码；未找到则 web_search 确认
- **模式判定（8/26 实战新增）**：
  - **首次扫描**：`wiki/entities/` 无该标的 `*-深度扫描-*.md` → 全量建档（输出完整基本面/公告/资金/技术/商品锚）
  - **增量复扫**：存在基线文件（如 `南山铝业-深度扫描-2026-08-21.md`）→ **先读基线**，输出聚焦：「基线 vs 现状」支柱对比 + 逻辑验证结论 + 规则触发对照（不重复全量收集）

### Step 2: 并行获取数据

> ⚠️ **本机 HTTPS 现状**：Windows schannel 出站 TLS 损坏（`SEC_E_NO_CREDENTIALS`），curl/Invoke-WebRequest 不可用；统一用 `dsh-market.mjs`（node.fetch/OpenSSL，已验证可用）。
> ```bash
> MK="$HOME/.dsh/skills/_shared/dsh-market.mjs"
> ```
> 行情类 → `index/stocks/sector/sina/kline`；抓 HTML 页（公告/研报）→ `get "<url>"`。

1. **实时行情**：`node "$MK" stocks "{code}"` + `node "$MK" sina "sh{code}"` 交叉；PE/PB/市值若需要，走东财 F10 数据或要求用户补充
2. **K线（8/26 起标准步骤）**：`node "$MK" kline "SH{code}" 101 30`——用于量价趋势、**量价背离判断**（8/26 实测：缩量上涨 70% 萎缩=关键警报）、关键位（前高/前低/支撑压力）
3. **商品锚核验（持仓标的必做，8/26 起）**：按 trading-daily-review 的「持仓商品锚映射表」抓对应期货（如南山=氧化铝 nf_AO0/沪铝 nf_AL0、紫金=金/铜、宝丰=布油/PE-PP）；周期/资源股即使非持仓也应做商品上下文——**商品异动必须 web_search 核实驱动**（如巴西减产→复产）
4. **近期公告**：`node "$MK" get "https://data.eastmoney.com/notices/stock/{code}.html"`；空则回退 np-anotice/web_search；提取近30天公告标题和类型
5. **机构评级**：`node "$MK" get "https://data.eastmoney.com/report/stock/{code}.html"`——**常为空，空则自评替代并标注"自评"**
6. **资金流向**：三层代理（见数据源段）：①`sector` 板块对比 ②`kline` 量能趋势 ③Vault 复盘主力记录；个股主力明细提示用户终端复核
7. **财务数据**：`node "$MK" get "https://emweb.securities.eastmoney.com/PC_HSF10/NewFinanceAnalysis/Index?type=web&code={code}"` 抓近4季度关键指标；或复用既有 entity/复盘已核数据
8. **舆情/事件**：web_search 近期新闻 + **事件驱动核实**（异动必核）

> 说明：DSH 无 `webfetch` 工具；`get` 用 node.fetch 抓 HTML 转纯文本（含导航噪音，需截取正文片段）。结构化行情数据优先走 `index/stocks/sector`。

### Step 3: 整合分析（按模式）

- **首次扫描**：按输出格式全量整合
- **增量复扫**：核心结构 = 「**逻辑支柱状态 × 时间**」对比表（如高股息 ✅→✅ / 氧化铝α ✅→❌）+ 变化证据链（数据+来源链接）+ **结论：持仓逻辑是否变化**（✅/⚠️/❌ 边缘 + 一句定性）——8/26 实战范式：从"双支柱"到"单支柱"判定

### Step 4: 关联现有持仓 + 规则触发对照

读取 `{VAULT_PATH}/交易体系/交易计划/当前持仓.md` 及对应 `*-操作规则.md`：
- 若标的在持仓中 → **逻辑支柱表**（每个支柱 ✅/⚠️❌ + 证据）+ **规则触发对照表**（操作规则各档位 vs 当前价/商品锚——未触发/接近/已触发）+ 标注当前逻辑状态与变化
- 若标的在待入场计划中 → 标注入场条件完成度变化
- 若不在持仓/计划中 → 标注"观察中"
- **产出建议分级**：观察（无触发）/ 专题讨论（需用户裁决）/ **自动执行（已预授权纪律线，如南山 4.60）**——区分"提示"与"执行"

### Step 5: 写入文件

输出路径：`{VAULT_PATH}/wiki/entities/{股票名}-深度扫描-{YYYY-MM-DD}.md`
- **复扫文件必须标注基线链接**（related 中含 `[[{股票名}-深度扫描-{基线日期}]]`）并在报告首节写明对比基线
