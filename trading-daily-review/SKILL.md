# 每日复盘工作流

> **Vault 路径**：`{VAULT_PATH}`（占位符，由 agent 从 MEMORY.md 读取本机实际路径后替换）。
> ⚠️ 本 Vault 可能在 OneDrive 下，大量/频繁写入可能触发同步延迟与文件锁——单篇读取、少量写入安全；批量写入建议分批。

## 核心原则

1. **预期-验证闭环**：每日复盘提出假设，次日早盘验证，形成闭环
2. **数据驱动**：所有判断必须有数据支撑，不用感觉代替事实
3. **连贯性验证**：每日复盘必须回顾前日预测，判断正确/偏差/遗漏
4. **可验证假设**：每次复盘结束必须提出至少一个可验证假设
5. **复盘与交易计划分离**：复盘只分析市场，不关联持仓；交易计划只定义执行规则
6. **三日窗口**：复盘基于今天 + 前两个交易日，不多不少
7. **计划你的交易，交易你的计划**：入场前所有决策已定好，盘中只执行不决策
8. **时间校验**：每个阶段开始前必须先获取当前日期/时间，确认今日日期、前一交易日、前二交易日，避免日期错误
9. **前日复盘追溯**：必须关联前两个交易日的复盘文件。如某交易日无复盘文件，继续向前追溯，直到找到两个有效复盘文件

## 数据双源校验（本机 HTTPS 修复前：东财工具 + 新浪交叉比对）

> ⚠️ 本机 Windows schannel 出站 TLS 损坏（`SEC_E_NO_CREDENTIALS`），**curl 与 xueqiu 工具均不可用**。行情取数统一走 `dsh-market.mjs`（node.fetch/OpenSSL）：
> ```bash
> MK="$HOME/.dsh/skills/_shared/dsh-market.mjs"
> node "$MK" index / stocks "..." / sector / sina "sh600519,..." / kline "SH600519" 101 120
> ```

行情读数以**东方财富（`index/stocks`）为口径基准**（沿用 MEMORY 中量能外推、成交额锚点等既有修正规则），**新浪（`sina`）做交叉复核**（含买卖盘）：

| 用途 | 工具 | 说明 |
|------|------|------|
| 指数/多标的口径 | `dsh-market index/stocks` | 东财主数据，成交额为准 |
| 交叉复核 | `dsh-market sina` | 新浪实时含 bid/ask，与东财比对 |
| K线 | `dsh-market kline` | 东财K线，无图表仅数据（101/102/103/5/15/30/60） |
| 板块资金 | `dsh-market sector` | 主力净流入方向 |
| 页面抓取 | `dsh-market get "<url>"` | 公告/研报/财务页转纯文本 |

**冲突规则（硬性）**：东财与新浪数值不一致时，在复盘"核心判断 / 今日验证"中**显著标注**（如 `⚠️ 数据冲突：东财 vs 新浪`），**不自动取信任一**；量能/成交额类校正以东方财富口径为准。此规则与"数据驱动、矛盾检测"铁律一致——数据打架本身就是要记录的现象。

> 注：之前规划的 `xueqiu_*` 雪球工具因 schannel 问题暂不可用；若日后 schannel 修复、雪球工具可用，本节改回"东财 + 雪球"双源，规则不变。

## 交易铁律（权威规则，优先于任何泛化判断）

1. **复盘第一步：识别市场状态**（趋势市 / 震荡市 / 轮动市）——所有后续判断以此为基准
2. **缩量分歧框架**：连续缩量 = 分歧未解；轮动确立需"放量 + 延续性"双条件
3. **轮动市空仓观望**：板块快速切换时，不追轮动；宁可错过不追高
4. **预判错误必须指出**：方向错误标 ❌、烈度偏差标 ⚠️、遗漏因素列出——复盘价值在于纠错
5. **假设必含对冲**：每个可验证假设须写明"如果判断错了会怎样"
6. **前提失效重估**：盘前/盘中出现计划外重大变化 → 标记 ⚠️"前提失效，暂停执行"，只冻结不自动改，修正由用户盘后决定
7. **盘中验证写入独立文件**：路径 `交易体系/盘中验证/YYYY-MM-DD 盘中验证.md`；同一日多次验证追加 `## 盘中验证 {HH:MM}` 章节，不再写入前日复盘
8. **盘中纪律**：盘中只执行已制定计划，不临时修改交易计划
9. **交易计划三形态**：①当前持仓.md（底档）②综合操作计划（YYYY-MM-DD 周X操作计划.md）③单标情景计划（A/B/C/D + 关键价位 + 止损）
10. **盘后第4步：制定明日交易计划**——基于当日复盘可验证假设 + 明日关注点 + 本周关键事件显式输出，经用户确认后生效
11. **交易计划必须经用户确认**：所有交易计划（含综合操作计划与单标情景计划）须经用户确认后才创建
12. **复盘文件必须全部保留**：不得删除历史复盘文件
13. **复盘与交易计划分离**：复盘只分析市场，交易计划只定义执行规则，交叉点仅在审查环节
14. **盘后第5步：记忆提炼**——复盘完成后判断是否需要生成/更新交易记忆（`交易体系/交易记忆/`）：
    - **重大事件**（减仓/止损/回补/规则变更）→ 新建 `YYYY-MM-DD-交易记忆-主题.md`（domain-memory 格式：预测/假设 + 实际结果 + 偏差分析 + rules + confidence）
    - **模式计数**（二日游N次/量能高估N次）→ 更新既有记忆文件计数，不重复新建
    - **规则修正**（锚点/纪律变更）→ 用户确认后同步更新 MEMORY.md 快照
    - **主次关系**：MEMORY.md=索引+稳定规则；交易记忆=事件详情；每日复盘=流水；wiki=知识
    - **矛盾检测**：发现与既有记忆冲突时，以"交易记忆+每日复盘"为准，并在新记忆的偏差分析中标注

## 工作流三阶段

### 阶段一：盘前准备（9:00前）

**前置步骤：时间校验**
```bash
# 获取当前日期，确认交易日
date "+%Y-%m-%d %A"
# 确认前一交易日、前二交易日日期
```

**输入**：
- 前两个交易日复盘文件（`{VAULT_PATH}/交易体系/每日复盘/`）
- 当日财经早读（`{VAULT_PATH}/交易体系/财经早读/`）
- 前日盘前预测和交易观察清单（`{VAULT_PATH}/交易体系/盘前预测/`）
- 交易计划文件（`{VAULT_PATH}/交易体系/交易计划/`）

**步骤**：
1. **追溯前两个交易日复盘**：读取最近两个交易日的复盘文件，如某日无复盘文件则继续向前追溯
2. 读取前日复盘的"明日关注点"和"可验证假设"
2. 读取当日财经早读，提取关键信息
3. **审查交易计划**：读取所有状态为"等待入场"或"持仓中"的交易计划，检查：
   - 入场条件是否接近触发（接近触发时主动提醒用户）
   - 已持仓计划的前提是否还成立（市场方向是否发生重大变化）
   - 失效条件是否已被触发
4. **持仓商品锚核验**：抓取持仓对应大宗商品价格（代码与表见"数据获取方式"节），对照各标的操作规则活文档的锚点（金价/铜/铝/氧化铝/油价/烯烃等），输出核验表——**验证持仓逻辑是否仍成立 + 辅助今日预判**（8/26 起固定环节）
5. 制定观察清单和盘前预测，写入本地文件（`交易体系/盘前预测/`）

**交易计划审查输出**：
```markdown
### 交易计划审查
- [计划名称]：[状态] — [审查结论]
  - 入场条件：[是否接近触发]
  - 前提是否成立：[是/否，理由]
  - 操作建议：[继续等待 / 有介入机会 / 建议失效]
```

**观察清单结构**（本地文件）：
```
第一层：市场整体量能
  - 成交额判断标准（>2.8万亿=确立；2.5-2.8万亿=试探；<2.5万亿=萎缩）

第二层：板块龙头量能验证
  - 各方向龙头个股+判断标准

第三层：科技分化信号
  - 关键标的+判断标准

决策树
  - 放量>2.8万亿？是→连板=确认；否→缩量→观望
```

**数据获取方式（本机 curl/HTTPS 不可用，统一走 node-fetch 行情工具）**：
```bash
# 行情工具路径（node 内置 OpenSSL，绕开 schannel 故障）

# 指数行情（上证/深成/创业板/沪深300/科创50）

# 个股行情（代码前缀：1=沪市,0=深市）

# 板块资金流向（前20）
node "$MK" sector 20

# 新浪实时（GBK自动解码，含bid/ask）
node "$MK" sina "sh600519,sz000001"

# K线（日K/周K/月K，period=101/102/103；分钟=5/15/30/60）
node "$MK" kline "SH600519" 101 120

# 持仓商品锚核验（国内期货 + 原油）
node "$MK" sina "nf_CU0,nf_AL0,nf_AO0,nf_RU0,hf_OIL,hf_CL,nf_L0,nf_PP0"
```

### 阶段二：盘中验证（10:00 / 13:00）

**时机**：
- 早盘验证：10:00-10:30
- 午盘验证：13:00-13:30（如有反转）

**步骤**：
1. 拉取实时数据（指数+观察标的+板块资金流向）
2. 逐条对照观察清单验证
3. **交易计划跟踪**：检查是否有交易计划的入场条件接近触发，如有则提醒用户
4. 更新本地交易观察清单（添加"盘中验证 HH:MM"章节）

**验证结果格式**：
```markdown
## 盘中验证 HH:MM

- 两市成交额~XXX亿，推算收盘X.X万亿，[试探/确立/萎缩]
- [方向1]：[结论]（龙头个股数据）
- [方向2]：[结论]（龙头个股数据）

### 交易计划跟踪
- [计划名称]：入场条件 [接近/未接近] 触发

### 操作决策
- [决策]：[原因]
```

**提醒规则**：
- 入场条件满足80%以上 → 主动提醒"有介入机会，是否制定/执行交易计划？"
- 已持仓计划触发止损线 → 立即提醒
- 市场出现重大方向变化可能影响已有计划前提 → 提醒审查

### 阶段三：盘后复盘（15:00后）

**前置步骤：时间校验**
```bash
# 获取当前日期，确认今日为交易日
date "+%Y-%m-%d %A"
# 确认前一交易日、前二交易日日期
# 如前一交易日无复盘文件，继续向前追溯直到找到两个有效复盘文件
```

**输入**：
- 当日完整交易数据
- 盘中验证结果
- 前两个交易日复盘文件（必须追溯找到两个有效文件）
- 交易计划文件

**输出**：
- 更新前日复盘的"今日验证"章节
- 创建当日复盘文件（包含"前日复盘回顾"章节，关联前两个交易日）
- **审查所有交易计划**：复盘完成后，检查每个交易计划的前提是否因当日行情而改变

**关键规则**：
> 早盘验证写入前日复盘，形成"预期-验证"闭环。当日复盘在收盘后创建，因为早盘仍有反转不确定性。

**复盘后交易计划审查**：
1. 读取 `交易体系/交易计划/` 下所有状态非"已完成"或"已失效"的计划
2. 对照当日复盘结论，检查计划的"决策依据"是否仍成立
3. 检查"失效条件"是否已被触发
4. 更新计划的审查记录：
   - 前提成立 → 记录"审查通过，继续等待"
   - 前提动摇 → 记录"审查警告：[具体变化]，建议关注"
   - 前提不成立 → 标记计划失效，移入归档
5. 如有新建交易计划的需求（观察清单中出现新机会），提醒用户

**复盘后归档检查**：
创建当日复盘文件后，检查 `交易体系/每日复盘/` 目录，将超过前两个交易日的复盘文件移入 `存档/` 子目录。主目录仅保留今日、前日、前前日三个交易日的复盘文件。
```bash
# 获取目录中所有复盘文件，按日期排序
ls "{VAULT_PATH}/交易体系/每日复盘/"*.md | sort
# 将早于前前日的文件移入存档
mv "{VAULT_PATH}/交易体系/每日复盘/YYYY-MM-DD 每日复盘.md" "{VAULT_PATH}/交易体系/每日复盘/存档/"
```

**复盘后记忆提炼（第5步，必做）**：
创建当日复盘文件后，按以下规则维护 `交易体系/交易记忆/`：

1. **扫描今日是否发生"记忆事件"**：
   - 重大交易动作：减仓/加仓/止损/止盈/回补（含否决案例）
   - 规则修正：锚点变更/纪律调整/用户新确认规则
   - 模式演进：二日游次数/量能高估次数/新结构信号（如"板块弱个股强"）
   - 新教训：预判重大错误或重大正确（confidence 评估）
2. **执行**：
   - 新主题 → 创建 `YYYY-MM-DD-交易记忆-主题.md`（格式见下）
   - 既有主题计数 → 编辑更新（如"科技硬件五次二日游"），不重复新建
3. **格式**（domain-memory，与 obsidian-reconcile/domain-memory skill 兼容）：
```markdown
---
type: domain-memory
domain: trading
created: YYYY-MM-DD
tags: [主题1, 主题2]
related: ["[[关联复盘]]", "[[关联记忆]]"]
rules:
  - 提炼的规则1
  - 提炼的规则2
confidence: high/medium/low
---

## 预测/假设
（当时的判断与隐含假设）

## 实际结果
（数据验证结果，✅/❌/⚠️）

## 偏差分析
（根因、认知升级、规则修正）
```
4. **同步 MEMORY.md 快照**：规则修正类（锚点/纪律）在用户确认后更新 MEMORY.md 的"持仓规则快照"；价格/状态类易变信息**只写 Vault，不写 MEMORY**
5. **每日复盘文件中关联**：当日复盘尾部"数据关联"加入新建的交易记忆链接

- 观察清单：搜索页面标题获取

**jq + curl 写入方式**（避免 JSON 编码问题）：
```bash
# 构建 JSON
jq -n '{
  children: [
    {object: "block", type: "heading_2", heading_2: {rich_text: [{type: "text", text: {content: "{日期} 复盘"}}]}},
    {object: "block", type: "paragraph", paragraph: {rich_text: [{type: "text", text: {content: "复盘内容..."}}]}}
  ]
}' > /tmp/notion_blocks.json

curl -s -X PATCH "https://api.notion.com/v1/blocks/{block_id}/children" /
  -H "Authorization: Bearer $NOTION_TOKEN" /
  -H "Notion-Version: 2022-06-28" /
  -H "Content-Type: application/json" /
  -d @/tmp/notion_blocks.json
```

## 常见错误

1. **时间混淆**：Notion API返回UTC时间，需+8小时转换为东八区
2. **早盘验证写错位置**：应写入前日复盘的"今日验证"，不是当日复盘
3. **图片占位符**：markitdown转换会生成`![](data:image/jpeg;base64...)`，需清理
4. **JSON编码**：使用 `jq` 构建 Notion API 请求体，不要手动拼接 JSON 字符串
5. **复盘中关联交易计划**：复盘只分析市场，不关联持仓。交易计划的审查在复盘完成后独立进行
6. **盘中临时修改交易计划**：交易计划一旦制定，盘中只执行不修改。修改只能在盘后审查时进行
7. **交易计划制定无人工参与**：MiMo可以提醒有介入机会，但交易计划必须经用户确认后才创建
8. **前日复盘只追溯一天**：必须关联前两个交易日的复盘文件，如某日无复盘文件则继续向前追溯
9. **日期错误**：每个阶段开始前必须先获取当前日期，确认今日、前一交易日、前二交易日
